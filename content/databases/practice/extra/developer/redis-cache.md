## Мета

Реалізувати класичний патерн cache-aside: гарячі дані читаються з Redis,
база залишається джерелом істини.

## Перед виконанням

- Патерн cache-aside. Що шукати: *cache-aside pattern*.
- Час життя ключа (TTL/expiration) у Redis.
- Інвалідація кешу і чому це одна з двох найважчих задач у програмуванні.

## Завдання

У вашому додатку для операцій читання:

1. **Читання**: спочатку шукаємо у Redis; якщо промах — читаємо з бази
   і кладемо у Redis з **expiration** (TTL оберіть і обґрунтуйте).
2. **Запис/оновлення/видалення**: пишемо у базу, після чого **інвалідуємо**
   відповідний ключ у кеші.
3. **Деградація**: якщо Redis недоступний — додаток не падає, а працює
   напряму з базою і пише попередження у лог. Продемонструйте: зупиніть
   Redis посеред роботи додатка.
4. Заміряйте час читання одного й того самого запису: з бази, з кешу.

## Як здавати

Pull request з кодом і замірами. У описі PR — обраний TTL і чому саме такий.
