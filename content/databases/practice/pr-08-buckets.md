## Мета

Навчитися працювати з об'єктним (файловим) сховищем через абстракцію:
одна й та сама логіка додатка, а файли лежать або на диску, або у бакеті Azure.

## Чому бакети — це круто

Бакет (object storage: Azure Blob Storage, Amazon S3, Google Cloud Storage) —
це сховище, яке зберігає файли як **об'єкти**: вміст + метадані + унікальний ключ.
Чому весь світ зберігає файли саме так, а не на диску сервера:

- **Практично безмежний обсяг** і копійчана ціна за гігабайт — платите лише
  за те, що реально лежить.
- **Доступ по HTTP**: кожен об'єкт має URL, файл можна віддати користувачу
  напряму або через тимчасове підписане посилання, минаючи ваш сервер.
- **Надійність**: хмара сама тримає кілька копій, версіонування захищає
  від випадкового перезапису.
- **Масштабованість**: тисяча користувачів одночасно завантажує файли —
  і це не ваша проблема, а проблема хмари.

Саме тому аватарки, документи, бекапи, відео та статика майже будь-якого
сучасного сервісу живуть у бакетах, а не в базі даних і не на диску сервера.

## Перед виконанням

Теми, які варто розібрати:

- Object storage vs файлова система: у чому концептуальна різниця.
  Що шукати: *object storage vs file storage*.
- Azure Blob Storage: storage account, контейнер, blob.
  Що шукати: *Azure Blob Storage quickstart Python*, *azure-storage-blob*.
- Завантаження файлів частинами: block blobs, `stage_block` /
  `commit_block_list`. Що шукати: *Azure block blob upload in chunks python*.
- Читання файлів частинами (чанками) у Python, щоб не тягнути
  весь файл у пам'ять. Що шукати: *python read file in chunks*.

## Завдання

1. **Придумайте, які файли мають сенс для вашого варіанта** — фото
   співробітника, обкладинка книги, скан квитка, договір постачальника...
   Що саме — вирішуєте ви, але файли мають бути прив'язані до вашої сутності.
2. Спроєктуйте інтерфейс файлового сховища (той самий підхід repository,
   що й у ПР7, але для файлів). Мінімальний набір операцій:
   - `Upload` — завантажити невеликий файл одним викликом;
   - `InitializeUploadSession` → `UploadPart` → `CompleteUploadSession` —
     завантаження великого файлу частинами;
   - `Download` — отримати файл;
   - `Delete` — видалити;
   - `List` — список файлів **з пейджингом** (привіт, ПР1).
3. Зробіть **дві реалізації** цього інтерфейсу:
   - **файлова система** — для локальної розробки: файли у папці,
     сесія завантаження — тимчасова папка з частинами, `Complete` склеює їх;
   - **Azure Blob Storage** — реальний бакет у хмарі (пакет `azure-storage-blob`);
     для сесій використовуйте block blobs.
4. Додайте **перемикач** між сховищами — за аналогією з перемиканням
   баз даних у [ПР7](/c/databases/practice/pr-07-storage).
5. Інтегруйте сховище у ваш консольний додаток: сутність вашого варіанта
   отримує пов'язані з нею файли.

## Як здавати

Pull request з кодом. У описі PR вкажіть: які файли ви прив'язали до своєї
сутності, як перемикати сховища і як ви тестували Azure-реалізацію.
