# LabHub — дорожня карта

Місія проекту: **якісна практична освіта, безкоштовна і доступна кожному**.
Без сертифікатів, без реєстрацій, без оплат — відкритий сайт, відкритий
репозиторій, здача робіт через pull request. Довгостроковий вектор — не
«сайт одного викладача», а **відкрита бібліотека практичних матеріалів**
(орієнтир жанру — metanit.com, але навколо лабораторних і практики) плюс
платформа, на якій будь-який викладач заводить свій курс за вечір.

Свідомо **не робимо**: офіційне оформлення навчання (сертифікати, набори,
зобов'язання), платні функції, продукти поза освітньою місією.

## Північна зірка (горизонт ~3 роки)

Платформа високоякісних курсів від різних авторів — за духом як Prometheus,
але **повністю безкоштовна і збудована з урахуванням епохи ШІ**: курси
пишуться у зв'язці «викладач + ШІ» (наш власний робочий процес — перший
доказ, що це дає якість за тижні, а не роки), чистий markdown-корпус —
готовий ґрунт для ШІ-тьютора поверх матеріалів, а самі курси проєктуються
у припущенні, що в кожного студента вже є ШІ-помічник. Рейтинги, профілі
авторів, облік прогресу — з'являться тоді, коли будуть автори і студенти,
яким вони потрібні: **контент і якість попереду платформи**. Markdown —
не обмеження, а стартова смуга: все, що накопичимо, конвертується у
будь-яку майбутню форму без втрат.

Статус курсу мереж: восени 2026 його читає інший викладач, нашого пілота
по ньому не буде. Курс **лишається на сайті цілком** — це відкритий
матеріал, ним можуть користуватися будь-чиї студенти; правки — лише
за фактичними помилками.

## Етап 0. Підготовка (вересень 2026, 1–2 тижні)

Мета — підготувати платформу до двох живих аудиторій одразу.

Чистка коду: з застосунку вирізається мертва серверна частина часів
Azure — адмінка, Google OAuth, webhook, завантаження контенту з GitHub
на льоту. Залишається чистий генератор «markdown → сайт»; тести
підрізаються, пайплайн пришвидшується. Це ж перший крок до платформи
для чужих викладачів: форкати простий код легше.

Зворотний зв'язок — **оцінка матеріалів студентами**: під кожною
сторінкою коментарі та реакції через giscus (GitHub Discussions, нуль
інфраструктури). Обмеження чесно визнаємо: потрібен GitHub-акаунт —
для студентів БД це навіть корисна звичка, для школярів Python додаємо
запасний канал (анонімна форма, посилання у футері).

Критерій готовності: код без мертвих гілок, giscus працює під сторінками
обох курсів, форма для школярів висить.

## Етап 1. Пілот платформи: БД + Python (осінній семестр 2026)

Через сайт ідуть **два курси одночасно** — «Бази даних» (ПР1–ПР8, екстра-
гілки, ВМ-практика) і «Python для школярів» (теми 1–8, домашки, летучки).
Дві дуже різні аудиторії — це навіть кращий тест платформи, ніж один курс
мереж: student experience школяра і другокурсника відрізняються сильно.

Правило етапу: контент курсів правиться лише точково. Ведеться журнал
пілота (файл у репозиторії): де застрягають, що питають, які сторінки
збирають «незрозуміло» у реакціях, чи користуються ключами до летучок.

Критерій успіху: обидві когорти пройшли семестр через сайт, журнал
заповнений, зібраний пріоритезований список правок і платформенних хотілок
від живих людей.

## Етап 2. Платформа для викладачів (паралельно, низька інтенсивність)

Мета — щоб чужий викладач завів свій курс, не спілкуючись з нами:
template-репозиторій з порожнім `content/` та інструкцією «форкни →
markdown → увімкни Pages → пушни»; розділ README для викладачів
(front-matter, треки, формули, врізки, летучки). Просування без бюджету:
GitHub topics, пости у профільних спільнотах (DOU, освітні чати).

Критерій успіху: перший чужий курс, заведений без нашої допомоги.

## Етап 3. Мультимовний контент

Найбільша платформенна фіча карти. Механізм мовних версій сторінки
(українська — основна, англійська — друга): паралельні файли за
конвенцією (`page.md` + `page.en.md`), перемикач мови на сторінці,
коректний фолбек «немає перекладу — показуємо основну». Зачіпає
завантажувач контенту, роутинг, UI та експортер — тому окремий етап,
а не пункт беклогу. Відкриває і курси для ширшої аудиторії, і платформу
для викладачів поза Україною.

Робити після того, як пілот доведе, що поточна структура контенту
стабільна: мультимовність поверх рухомої структури — подвійна робота.

## Етап 4. Методички з контенту (розвідка)

Ідея: та сама markdown-праця стає офіційною методичкою кафедри —
титульний лист, вихідні дані, наскрізна нумерація, друкований формат.
Спершу **розвідка обсягу зусиль**: прототип конвеєра
«курс → docx/PDF» (pandoc + шаблон титулки за вимогами кафедри) на
одному курсі БД. Якщо прототип показує, що це тиждень, а не місяць, —
ставимо у план; якщо місяць — свідомо відкладаємо.

Критерій рішення: прототип методички одного курсу + чесна оцінка часу
на доведення до вимог кафедри.

## Етап 5. Кандидати наступного року

Курс .NET (спеціальність викладача; відкривається відкладеною лекцією
«Еволюція HTTP» з gRPC, повертає Docker/k8s/OTel) — якщо навантаження
наступного року його дасть. Навчальні інструменти (візуалізатор TCP,
пісочниця «збери TLS», SQL-тренажер) — по одному, лише закінчені, лише
якщо підсилюють живі курси.

## Технічний беклог (без прив'язки до етапів)

Пошук по сайту (статичний індекс + lunr.js); власний домен; скріншоти
для git-гайдів у «Загальному»; ужимання ЛР5 курсу мереж до трьох завдань
(якщо інший викладач попросить).
