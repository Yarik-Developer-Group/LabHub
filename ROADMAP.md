# LabHub — дорожня карта

Місія проекту: **якісна практична освіта, безкоштовна і доступна кожному**.
Без сертифікатів, без реєстрацій, без оплат — відкритий сайт, відкритий
репозиторій, здача робіт через pull request. Готовність до роботи доводиться
портфоліо зданих лаб, а не папірцем.

Свідомо **не робимо**: офіційне оформлення (сертифікати, набори, зобов'язання),
платні функції, продукти поза освітньою місією.

---

## Етап 0. Підготовка до пілота (вересень 2026, 1–2 тижні)

Мета — прибрати все, що заважає, до приходу першої когорти.

Що змінюється в коді: з застосунку вирізається мертва серверна частина, яка
мала сенс лише на Azure-хостингу — адмінка, Google OAuth, webhook
`/api/content/refresh`, завантаження контенту з GitHub на льоту. Залишається
чистий генератор «markdown → сайт» з локальним переглядом; тести
підрізаються відповідно, пайплайн пришвидшується.

Що з'являється: канал зворотного зв'язку від студентів **до** старту пілота —
щонайменше giscus (коментарі через GitHub Discussions) або проста форма;
без нього пілот пройде наосліп.

Контроль якості: власний прохід ключових лаб (ЛР1–ЛР3, ЛР6–ЛР8) очима
студента — «на скільки складно ми нахімічили».

Критерій готовності: код без мертвих гілок, сайт живий на Pages, канал
фідбеку працює, викладач пройшов лаби сам.

## Етап 1. Пілот курсу мереж (осінній семестр 2026)

Головний етап року. Мета — **не вчити курс, а виміряти його**: перша когорта
проходить ЛР1–ЛР8, теорію і летучки, а ми збираємо факти замість припущень.

Правило етапу: курс заморожений. Правки — лише точкові (помилки, незрозумілі
формулювання), жодних нових тем і перебудов посеред семестру.

Що фіксуємо по ходу (журнал пілота — файл у репозиторії): на якій лабі
застрягають і чому; скільки доходять до фінальної ЛР8; які питання звучать
на захистах; чи читає хтось екстра-лекції та екстра-лаби; чи користуються
ключами до летучок.

Рішення, які ухвалюємо за підсумками: чи ужимати ЛР5 з п'яти завдань до
трьох; чи повертати щось із вирізаного (VPN-лекція); чи потрібна телеметрія
в основній програмі; що з крипто-лекції виявилося занадто.

Критерій успіху: когорта дійшла до кінця, журнал пілота заповнений, список
правок на наступний рік складений і пріоритезований.

## Етап 2. LabHub як продукт для викладачів (паралельно, низька інтенсивність)

Платформа «markdown-курс → безкоштовний сайт» потрібна не лише нам:
викладачів із матеріалами, що гниють у docx, — тисячі. Мета етапу — щоб
чужий викладач міг завести свій курс за вечір, не спілкуючись з нами.

Що змінюється: створюється **template-репозиторій** — платформа з порожнім
`content/` і покроковою інструкцією «форкни → напиши markdown → увімкни
Pages → пушни»; README доповнюється розділом для викладачів (як влаштований
front-matter, треки, екстра-гілки, формули, врізки). Контент наших курсів
лишається в основному репозиторії — шаблон його не тягне.

Просування — без бюджету: GitHub topics, один-два пости у профільних
спільнотах (DOU, освітні чати), слово «безкоштовно» працює саме.

Критерій успіху: **перший чужий курс** на нашій платформі, заведений без
нашої допомоги.

## Етап 3. Курс .NET (зима–весна 2027)

Природне продовження: спеціальність викладача і затверджений план
наступного року вже дивляться сюди. Курс відкривається лекцією «Еволюція
HTTP: від тексту до QUIC» (з gRPC-епілогом — вона чекає у планах), далі
мікросервіси, і сюди ж повертається все свідомо вирізане з 2 курсу:
Docker/Compose, Kubernetes концептуально, OpenTelemetry і трейси
(екстра-лаба про кореляцію логів — місток).

Що зробити до старту: програму курсу (грудень 2026 — січень 2027),
зі структурою «лекції + лабораторні по 2–3 завдання + наскрізний проект»,
де наскрізний проект і є «мікросервісний» фінал.

Критерій готовності: затверджена програма і перші три лаби до початку
семестру.

## Етап 4. Навчальні інструменти (за настроєм, після пілота)

Маленькі інтерактивні речі, кожна з яких підсилює курси і живе на тих самих
Pages (чистий JS, нуль інфраструктури): візуалізатор TCP-рукостискання;
пісочниця «збери TLS із цеглинок»; SQL-тренажер до курсу БД. Правило: одна
річ за раз, тільки закінчені, тільки якщо реально допомагають лабам.

## Технічний беклог (без прив'язки до етапів)

Пошук по сайту (статичний індекс + lunr.js — знімок уже все знає);
giscus-коментарі під сторінками; власний домен (одна CNAME, коли захочеться
адресу без підпапки); скріншоти для git-гайдів у «Загальному».
